===============
Job monitoring
===============

This document describes the *health checks* that can be added to the job
configuration, as well as the *health report* that these checks are included in.

The Job Runner daemon, along with selected jobs can be monitored using a report
file generated by Job Runner itself.  The report is intended to be used with
Zabbix, but could probably also be used with other monitoring tools.

.. contents::
   :depth: 2
   :local:


Health Checks
==============
Jobs (``Actions``) are monitored by adding a ``health`` attribute.

This attribute is a ``HealthCheck`` object, with rules that define an
unacceptable *state* for the job:

``check_ok``
    Indicates that we care about the last exit state of this job.  If the job
    does not complete successfully, a Problem should be triggered in Zabbix.

    Example: ``Action(…, health=HealthCheck(check_ok=True))``

``check_overdue``
    Indicates that we care about the run frequency of this job.  If the job does
    not complete successfully at least once in the last *check_overdue* seconds,
    a Problem should be triggered in Zabbix.

    If a job should e.g run once an hour, we should probably consider it an
    issue if it doesn't complete a run in e.g. 2 or more hours.

    Example: ``Action(…, health=HealthCheck(check_overdue=2*3600))``

Any job where the ``Action.health`` attribute is set to a ``HealthCheck``
object is selected for inclusion in the `health report`_ ``discovery`` section.


Health Report
=============

Generating a report
--------------------
The report is generated by starting job runner with e.g.:
::

    python job_runner.py --health-report /cerebrum/var/run/job-runner-health.json



Report content
---------------
The health report is split into three sections:

``discovery``
    A list of jobs configured with health checks, and their health check
    settings.

    This section is intended to automatically create triggers in Zabbix, using
    the host/template discovery feature.

``jobs``
    The current state of *all* jobs (last run timestamp, last exit status, ...).

    This section is intended to populate *items* in Zabbix, which can both be
    used for triggers generated by the *discovery* section, or for general
    monitoring/statistics.

``state``
    The job-runner state.  This includes a timestamp for the current report, and
    a job runner pause start timestamp (if currently paused).

    This section is intended for overall monitoring of the job-runner daemon.


Example:
::

    {
      "discovery": [
        {
          "job_name": "example_job",
          "check_ok": true,
          "check_overdue": 3600,
        }
      ],
      "jobs": {
        "example_job": {
          "is_overdue": 0,
          "last_done_at": 1775764973,
          "last_success_at": 1775764973,
          "prev_msg": "ok",
          "prev_ok": 1
        }
      },
      "state": {
        "curr_time": 1775764980,
        "paused_at": 0
      }
    }


Using the report
-----------------
A typical monitoring setup should check for:

Missing or out-of-date reports.
    This happens e.g. if the report file is missing, unreadable, empty, or where
    ``state.curr_time < time() - <some threshold>``

Failed jobs
    This check should be enabled for jobs that appear in ``discovery`` with
    ``discovery[].check_ok == true``.

    A discovery job ``d`` should generally count as failed if
    ``jobs[d.job_name].prev_ok != 1``.

Overdue jobs
    This check should be enabled for jobs that appear in ``discovery`` with
    ``discovery[].check_overdue > 0``.

    A discovery job ``d`` should generally count as failed if
    ``jobs[d.job_name].is_overdue > d.check_overdue``

.. tip::
   The Zabbix service at the University of Oslo already includes a template for
   monitoring hosts with a job-runner daemon, ``Template-crb-jr-health``.

   By default the template will look for a report at
   ``/cerebrum/var/run/job-runner-health.json``, but the ``{$CRB_JR_REPORT}``
   Zabbix host macro can used to override this location.


Example
========
This minimal configuration example defines a single job with health check rules
for a health report.
::

    import sys

    from Cerebrum.modules.job_runner import job_actions
    from Cerebrum.modules.job_runner import job_utils
    from Cerebrum.modules.job_runner.health import HealthCheck
    from Cerebrum.utils.date import to_seconds


    class AllJobs(job_actions.Jobs):

        example_job = job_actions.Action(
            call=job_actions.System(
                '/usr/bin/bash',
                params=[
                    '-c', 'date >> /tmp/example-job.txt',
                ],
            ),
            when=job_utils.When(freq=to_seconds(minutes=10)),
            max_freq=to_seconds(minutes=1),
            health=HealthCheck(
                check_ok=True,
                check_overdue=to_seconds(minutes=40),
            ),
        )


    def get_jobs():
        alljobs = AllJobs()
        return alljobs.get_jobs()


    if __name__ == '__main__':
        job_utils.pretty_jobs_presenter(AllJobs(), sys.argv[1:])


See :doc:`config` for more info on how to configure jobs.
